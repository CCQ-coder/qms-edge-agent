# 飞针机文件采集程序设计

## 目标与范围

在 Windows 现场电脑上运行一个独立于现有 HTTP 监听程序的飞针机采集程序。它读取 `\\Scbgx\数字化\飞针机` 下的一级设备目录及目录内的 `.txt` 文件，把每个文件的当前测试计数快照发送至 QMS Telemetry v1。现有监听程序故障时，飞针机程序仍可单独运行、记录和补传。程序只读取共享目录，不修改或删除源文件。

首次启动采集全部现有有效 TXT 文件的当前快照；之后仅在文件快照变化时产生新事件。现场账户必须拥有共享目录读取权限，且 QMS 中已将设备目录名配置为对应设备的网关映射。

## 输入与字段映射

目录结构为 `<采集根目录>/<设备名>/<料号>.txt`。仅扫描根目录的一级子目录及其直接子文件，不递归更深层目录。设备目录名是 `machineName`，去掉 `.txt` 的文件名是 `materialNo`。文件的 Windows 创建时间是开始时间，最后修改时间是更新时间，均按现场电脑本地时间解释。

从文件中读取一行完整的计数记录，例如：

```text
Test_Counters 2 2 0 01:27:09
```

该行在 `Test_Counters` 后依次是已测板数、好板数、坏板数和上次测试时间。前三项必须是非负整数；最后一项按 `小时:分钟:秒` 验证，但作为原始字符串传递，不推断成绝对日期时间或持续时长。不强制要求已测板数等于好板数加坏板数。缺少记录、字段不完整或格式错误的文件只记录错误并等待下次扫描，不上报猜测值。

每个有效快照生成一条 `POST {QmsBaseUrl}/api/v1/equipment/telemetry` 事件，请求体为 `{ "events": [event] }`，使用 `X-Gateway-Token` 认证。生产 QMS 若启用服务账号认证，配置中还需提供 Bearer Token。事件字段如下：

| QMS 字段 | 值 |
| --- | --- |
| `machineName` | 一级设备目录名 |
| `materialNo` | TXT 文件名去扩展名 |
| `deviceTime` | 文件最后修改时间，`yyyy-MM-ddTHH:mm:ss` |
| `eventType` | `FLYING_PROBE_TEST_COUNTERS` |
| `machiningCount` | 已测板数 |
| `recordNo` | 由相对路径、创建/修改时间及 `Test_Counters` 的四个值生成的稳定摘要，前缀 `FPT-` |
| `attributes.sourceProtocol` | `FLYING_PROBE_TXT_V1` |
| `attributes.startTime` / `attributes.updatedAt` | 创建时间 / 最后修改时间，`yyyy-MM-ddTHH:mm:ss` |
| `attributes.testedBoardCount` / `goodBoardCount` / `badBoardCount` | 三个整数 |
| `attributes.lastTestTime` | 原始时间字符串，例如 `01:27:09` |
| `attributes.sourceFile` | 相对路径 `<设备名>/<料号>.txt` |

QMS 当前接受自定义 `eventType`，但好板数、坏板数和开始时间作为 `attributes` 保存在原始事件中；本项目不修改 QMS 页面或汇总模型。

## 运行与故障恢复

新增单独的控制台 EXE、INI 配置、构建脚本、启动脚本和使用说明；使用仓库现有的 .NET Framework 4.x 编译方式。配置包含采集根目录、扫描间隔、QMS 地址、网关令牌、可选 Bearer Token、请求超时，以及独立的本地队列、扫描状态和日志路径。配置文件和运行数据默认与程序放在同一发布目录下；敏感令牌不得写入仓库示例值。

程序定时轮询共享目录。仅当文件长度与最后修改时间在连续两次扫描中相同，才读取并解析；读取后再次检查这两个属性，变化则留待下轮处理，避免处理正在写入的文件。有效快照先持久写入本地待发送队列，再保存该文件的已采集快照标识；若两步之间崩溃，重启后可重复入队，但相同 `recordNo` 会使 QMS 幂等处理。队列和扫描状态使用本地原子文件替换；已有数据损坏时启动报错，不静默清空。

发送器对每条待发送事件单独请求 QMS。只有 HTTP `2xx` 才从队列删除该条事件；网络失败、认证失败、未配置设备映射或其他非 `2xx` 都保留事件并在后续轮询中重试，同时继续尝试其他事件，避免一台设备的问题阻塞其他设备。QMS 已接收而本地尚未删除时可再次发送同一 `recordNo`，由 QMS 去重。共享目录暂时不可访问时保持队列与扫描状态，记日志并在下轮重试。程序不依赖现有监听程序的进程、配置、队列或日志。

## 验证

使用临时目录和示例 TXT 测试目录/文件名、创建/修改时间、计数解析、格式错误、稳定文件检测、首次扫描与更新扫描、重启去重。使用本地 HTTP 测试服务验证请求字段、令牌、`2xx` 删除队列以及非 `2xx` 保留并继续处理其他事件。运行现有仓库的构建与契约检查，确认新程序不改变当前监听器。现场共享目录不可从本开发环境访问，最终需要在有读取权限的现场电脑上验证真实文件和 QMS 设备映射。
