# 标特福监控界面性能优化设计

## 目的与范围

现场预计同时连接 25 台锣机，每台约每秒发送一条状态。保留现有设备卡片和最近记录，降低设备增多时的界面卡顿与 CPU 占用。设备记录写盘、QMS 和 S1 上报仍逐条执行，不能因界面来不及绘制而漏报。

当前每条快照都会单独排入 WinForms UI 线程，重设该设备最多 200 行的文本框，并遍历所有设备更新状态。上报日志也逐条排入 UI 线程，每次读取整个全局日志框。约 25 台、两路每秒上报时，UI 每秒可能收到数十次回调，且每次操作的成本随历史行数或设备数增长。

## 方案选择

- **选定：保留卡片，批量刷新。** 网络线程只将待显示快照与日志放入有上限的内存缓冲区；UI 定时批量取出并追加文本。改动集中在监控窗口，保持现场使用习惯。
- **未选：设备列表加单台详情。** 只绘制可见设备，适合上百台，但需要重做界面布局及查看历史的流程；25 台暂无必要。
- **未选：先改网络或磁盘同步。** 250 毫秒读取超时及逐条强制落盘也有成本，但直接改动会影响无换行命令的解析时机或数据耐久性；先处理明确的 UI 热点，再依据现场 CPU 测量决定是否继续。

## 行为设计

1. `BtfServer` 对每条快照继续调用记录落盘、QMS/S1 入队及界面接收回调。界面接收回调不再为每条数据调用 `BeginInvoke`。
2. 增加线程安全的显示缓冲区，每台设备最多暂存 200 条待显示快照，全局日志最多暂存 1000 条，并保留各自顺序。满额时仅舍弃最早的**待显示**项，不影响已经落盘或入队的数据。
3. WinForms UI 每 250 毫秒最多处理一批：按设备一次追加本批文本，新增设备卡片后只重排一次；全局日志一次追加本批文本。设备卡片显示超过 240 行时成批修剪为最新 200 行，避免每秒重写整个文本框。全局日志超过 1000 行时保留最新 800 行。
4. 稳态下在线数和离线状态每秒计算一次，用户点击启动、停止或暂停时立即更新状态栏；设备标题只在状态变化时更新。在线判断使用快照**接收时刻**，避免 UI 忙碌导致误判离线。
5. “清空显示”同时清除尚未绘制的缓冲内容；停止监听后仍显示最终日志并可重新启动，关闭窗口时停止刷新定时器。配置、QMS/S1 发送频率及磁盘记录格式不变。

## 验证与交付

- 为缓冲区补测试：25 台周期数据、突发数据上限、各设备顺序、全局日志顺序、清空后不回显旧数据。
- 运行标特福原有测试和 Windows 构建；用合成的 25 台、每台每秒一条及上报日志流验证 UI 待处理量有界、窗口仍能响应操作。
- 构建新的 `BtfMonitor.exe` 发布文件，不覆盖现场已有的 `BtfMonitor.json`。若现场 CPU 仍偏高，再单独测量网络超时与逐条写盘成本。
